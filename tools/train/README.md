# Training Tools

These tools produce the models in `models/` that the crate embeds. They are
not part of the library and are not needed to use it.

| File | Purpose |
| --- | --- |
| `corpus.py` | Generates labeled synthetic samples. Standard library only. |
| `attacks.py` | Grammars of the six injection categories. |
| `obfuscation.py` | Obfuscating encodings and chains of them. |
| `formats.py` | More benign formats, and generated hard negatives. |
| `benign.py` | Benign text, the pools shared with attack carriers, and corruption of benign samples. |
| `dataset.py` | Joins some samples into longer ones and writes a corpus file. |
| `train.py` | Trains, quantizes, evaluates, and exports a model. Needs NumPy. |
| `models.json` | The data splits and the preset of every model. |
| `build_models.py` | Builds every model in `models.json`, from data to evaluation. |
| `test_*.py` | Tests of the tools. |

## Procedure

Run the commands from the repository root. `WORK` is any directory outside
the repository.

```sh
python3 -B tools/train/build_models.py --work "$WORK" --install
cargo test
```

`build_models.py` builds the `fingerprint_corpus` and `score` examples,
generates the splits that `models.json` lists, extracts their fingerprints,
trains every model, scores the development set in `tests/data/` with each
one, and with `--install` copies each model and its golden vectors to
`models/`. It skips a step whose output exists in `WORK` unless `--force` is
given, and `--only NAME...` builds the named models only. It prints a
summary table and writes `WORK/summary.json`.

The script runs these steps, which can also be run by hand:

```sh
set -e
cargo build --release --examples

for split in "train 1 600000" "val 2 60000" "test 3 60000"; do
  set -- $split
  python3 -B tools/train/dataset.py --seed "$2" --count "$3" --out "$WORK/$1.bin"
  target/release/examples/fingerprint_corpus "$WORK/$1.bin" "$WORK/$1.x" "$WORK/$1.y"
done

python3 -B tools/train/train.py --data "$WORK" --out "$WORK/out" --name default \
  --hidden 64 64 --epochs 16 --quantized-epochs 3 --seed 1

cp "$WORK/out/default.s2fp" models/default.s2fp
cp "$WORK/out/default.golden" models/default.golden
```

`train.py` writes `NAME.s2fp`, `NAME.golden`, and `NAME.json` with the
metrics. `--benign-weight` scales the loss of benign samples; a value above
1 trades recall for fewer false positives.

Every step is deterministic for its seed on one machine. Floating-point
training can round differently on another CPU or NumPy build, so a rerun
elsewhere gives a model with close but not identical parameters.

Features are extracted by the library itself through the `fingerprint_corpus`
example, so training sees exactly the features that inference computes. A
change to the fingerprint layout in `src/fingerprint.rs` invalidates the
model: regenerate the features and retrain in the same change.

`train.py` evaluates the quantized network with an integer simulation of the
arithmetic in `docs/design.md`. It writes golden vectors, each a fingerprint
followed by the scores that the simulation computed. The Rust test
`embedded_model_matches_golden_vectors_on_every_backend` replays them, which
ties the simulation, the model file, and every kernel together.

To run the tests of the tools:

```sh
python3 -B -m unittest discover -s tools/train -p 'test_*.py'
```

## Data

All training data is synthetic and generated by `corpus.py`. No recorded
traffic is used.

- About half of the samples are benign: generated prose in many scripts, code
  and configuration lines, header values, paths, query strings, form bodies,
  cookies, JSON, logs, and values with ordinary percent-escapes. `formats.py`
  adds the ordinary forms of the syntax that attacks abuse: rich-text HTML
  with links and images, parameterized SQL, command lines in documentation,
  translation placeholders, YAML, TOML, INI, XML, GraphQL, relative imports
  and asset paths that climb one or two levels, base64, JWTs, hashes, and
  Windows paths.
- Attack samples are generated from grammars for each category, optionally
  encoded, and placed in the same carriers as benign values: bare, query
  string, form body, cookie, path, prose, JSON, XML element or attribute,
  GraphQL argument, YAML value, HTML attribute, CSV cell, and the values of
  the `User-Agent`, `Referer`, `X-Forwarded-For`, `Cookie`,
  `Authorization`, `Content-Disposition`, and other headers.
- Each injection grammar in `attacks.py` draws an injection context, a
  technique, and the technique's operands independently. For example, SQL
  injection combines 15 breakouts, 12 techniques across five database
  dialects, generated tables, columns, and conditions, whitespace substitutes,
  and comment or quote-balancing terminators. Markup injection combines 33
  tags with 46 event handlers and 19 script sinks, and also covers attribute
  and script-string breakouts, URL schemes, XML external entities, CSS, and
  forms. Path traversal has 35 traversal units, about 80 sensitive files on
  Linux and Windows, stream wrappers, and UNC and drive paths. Command
  injection has about 60 POSIX and 30 Windows commands, 11 separators, quote
  breakouts, and space substitutes. Template injection covers more than 20
  engines and expression languages and generated Log4Shell lookups. Header
  injection has about 20 line-break forms, 25 injected headers, response
  splitting, request smuggling, and mail headers.
- A technique that hides its characters or keywords also sets the
  `obfuscation` bit, for example a double percent-encoding, an overlong or
  `%u` escape, a shell glob or quote that spells a command, a caret-escaped
  Windows command, or a nested Log4Shell lookup.
- Two labels follow from the shape of a payload, whichever grammar made it,
  so that the same shape always gets the same label. A reference to a
  well-known sensitive file by an absolute path, a file URL, or `../` units
  is `path_traversal`, also inside another attack, such as
  `load_file('/etc/passwd')`, an XML external entity, a template include, or
  `cat /etc/passwd`. A keyword split into concatenated strings, such as
  `top['al'+'ert']`, is `obfuscation`.
- Most `malformed` samples are a benign sample with exactly one structural
  damage, such as a truncated UTF-8 sequence, a character re-encoded in a
  legacy code page, a field cut inside its last character or percent-escape,
  a NUL byte, a terminal escape sequence, or a UTF-16 fragment. The clean twin
  stays in the corpus as a benign sample, so the damage is the only
  difference the model can learn from. The other `malformed` samples are
  generated whole: text in 15 legacy encodings, UTF-16 text, file headers of
  binary formats, surrogates, and invalid escapes.
- `obfuscation.py` has 20 techniques: double, triple, and partial double
  percent-encoding, `%u` escapes, overlong UTF-8 raw or percent-escaped,
  numeric character references, language and CSS escape runs, UTF-7,
  full-width, look-alike, mathematical, invisible, and combining characters,
  SQL comment and MySQL versioned-comment splitting, shell quote splitting,
  and JavaScript string concatenation. A sample applies one technique or
  chains one with one or two percent-encoding layers.
- Some `obfuscation` samples are a benign value with layered encoding, paired
  with its plain or single-layer form in the same way.
- A quarter of the attack samples get a second label: another payload
  appended before or after, a payload that is an attack in two categories at
  once (for example a command that reads a traversed file, or response
  splitting with a script body), an obfuscation, or a damaged byte.
- Hard negatives are benign samples that share vocabulary or punctuation
  with attacks. Most are generated: prose with SQL, shell, markup, path, or
  template words inserted, names with apostrophes, comparisons, quoted
  speech, lists with `;`, `|`, or `&`, code with `&&` and `||`, and header
  names in prose. The rest are fixed sentences of the same kinds.
- Every benign sample passes a final check in `benign.py` that rejects the
  forms that the attack grammars produce, so that no benign sample carries a
  payload by accident. `test_attacks.py` checks that the check rejects
  almost every generated payload and keeps almost every benign sample.
- `dataset.py` joins about a third of the samples with others, up to 512
  bytes, so that the model also sees dense windows and payloads surrounded by
  unrelated content. A joined sample has the labels of all of its parts.

## Measured Results

The embedded model has layers of 3072, 64, 64, and 8 units and is
202,336 bytes. It was trained with the procedure above.

On the synthetic test split, which holds 59,991 samples of which 21,446 are
benign, the quantized model scores as follows. Recall is the share of samples
of a category that score at or above the threshold in that category. The
benign rate is the share of benign samples that do.

| Category | Samples | AUC | Recall at 128 | Benign rate at 128 | Recall at 192 | Benign rate at 192 |
| --- | --- | --- | --- | --- | --- | --- |
| `malformed` | 11,943 | 0.994 | 94.6% | 0.08% | 93.7% | 0.02% |
| `obfuscation` | 12,620 | 0.993 | 91.7% | 0.17% | 88.9% | 0.07% |
| `sql_injection` | 7,913 | 0.992 | 90.1% | 0.10% | 86.1% | 0.05% |
| `markup_injection` | 8,287 | 0.997 | 93.9% | 0.07% | 91.3% | 0.03% |
| `path_traversal` | 9,248 | 0.993 | 89.3% | 0.16% | 84.9% | 0.08% |
| `command_injection` | 8,067 | 0.972 | 75.5% | 0.44% | 64.7% | 0.18% |
| `template_injection` | 7,974 | 0.992 | 88.7% | 0.09% | 83.2% | 0.04% |
| `header_injection` | 7,730 | 0.996 | 93.8% | 0.12% | 90.9% | 0.06% |

| Threshold | Benign samples flagged in any category | Attack samples flagged in any category |
| --- | --- | --- |
| 128 | 1.19% | 98.1% |
| 192 | 0.51% | 97.2% |
| 230 | 0.23% | 95.9% |

Quantization moves a score by 0.95 on average compared with the float
network.

The test split comes from the current generator, which produces far more
varied attacks, obfuscation, and benign look-alikes than the one that the
previous model was trained on. On this split the previous model flagged
5.79% of benign samples and 93.8% of attack samples in some category at
threshold 128, so the new data is harder and the retrained model does
better on it.

`tests/data/` holds a hand-written development set of 63 attack strings and
72 benign strings that do not come from the generator. At threshold 128 the
model flags 62 of the 63 attack strings in their own category and none of the
72 benign strings in any category. The previous model flagged 60 and 1.
`tests/model_quality.rs` fails when a model does clearly worse. The set was
consulted while the fingerprint layout and the training data were designed,
so it is not a held-out test set.

### Every Model

`build_models.py` trained the four presets of `models.json` on the same
splits. The crate embeds all of them, and `EmbeddedModel` names them. The
table gives the mean AUC over the categories and the share of test samples
flagged in any category at threshold 128, on the synthetic test split, and
the results on the development set.

| Model | Layers | Bytes | Mean AUC | Attacks flagged at 128 | Benign flagged at 128 | Development attacks | Development benign |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `compact` | 3072, 32, 8 | 98,906 | 0.989 | 97.2% | 1.24% | 57 of 63 | 0 of 72 |
| `default` | 3072, 64, 64, 8 | 202,336 | 0.991 | 98.1% | 1.19% | 62 of 63 | 0 of 72 |
| `large` | 3072, 192, 96, 8 | 611,424 | 0.992 | 98.5% | 1.03% | 61 of 63 | 0 of 72 |
| `strict` | 3072, 64, 64, 8 | 202,336 | 0.990 | 97.6% | 0.55% | 61 of 63 | 0 of 72 |

`strict` trades a little recall for half the benign rate of `default`.
`compact` misses more development strings than the others, and
`large` separates best on the synthetic split at three times the cost of
`default`. `tests/model_quality.rs` holds a limit for each model.

The presets of `Detector` pair these models with thresholds. Measured with
the library on the same test split, with `Dataset::evaluate` over the 59,991
samples of which 21,446 are benign:

| Preset | Model | Threshold | Attacks flagged | Benign flagged |
| --- | --- | --- | --- | --- |
| `fast` | `compact` | 128 | 97.2% | 265, 1.24% |
| `balanced` | `default` | 128 | 98.1% | 256, 1.19% |
| `thorough` | `large` | 128 | 98.5% | 222, 1.04% |
| `strict` | `strict` | 192 | 96.7% | 63, 0.29% |

The library rounds 222 of 21,446 to 1.04%, where the table above gives 1.03%
for `large`. On the development set the presets flag 57, 62, 61, and 58
attack strings in their own category and no benign string.

## Training With the Library

The `train` feature of the crate trains models without Python or NumPy, with
the procedure of `train.py`, and the `train` example runs it from the command
line. It reads the corpus files of `dataset.py` and text files, and it reports
the AUC, recall, and benign rate of each category on held-out samples:

```sh
cargo run --release --features train --example train -- \
  --corpus "$WORK/train.bin" --test-corpus "$WORK/test.bin" --out "$WORK/mine.s2fp"
```

The documentation at the top of `examples/train.rs` lists every option,
including the settings of `TrainConfig`, sample weights, and the costs of
false positives and false negatives in each category. Unlike `train.py`, the
library gives the same model bytes on every supported host.

With the settings of the `default` model, on 99,990 training samples (seed 1)
and 19,996 test samples (seed 3), the two trainers give models of the same
quality:

| Trainer | Mean AUC | Attacks flagged at 128 | Benign flagged at 128 | Time on four cores |
| --- | --- | --- | --- | --- |
| `train.py` | 0.9855 | 97.44% | 1.95% | 50 s |
| `train` example | 0.9850 | 97.26% | 2.09% | 13 s |

## Correcting a Model

`Trainer::fine_tune` of the `train` feature continues the training of a model
on new samples. This measurement tuned the embedded `default` model on 1,000
generated lines of documentation that quote shell commands and SQL
statements, which is the known false positive under [Limits](#limits). The
lines came from a one-off generator that is not in the repository, so the
numbers show the size of the effects and cannot be reproduced from this
tree.

Held-out lines of the same kind and lines built from other commands and
other sentences measure the correction. The synthetic test split of seed 3,
with 7,129 benign samples and 12,867 attacks, measures what the correction
costs. Each column is the share flagged in any category at threshold 128,
and the last one is the recall of `command_injection` alone.

| Tuning data | Settings | Same kind of lines | Other lines | Benign test samples | Attacks | `command_injection` recall |
| --- | --- | --- | --- | --- | --- | --- |
| None, the base model | | 64.4% | 78.3% | 1.16% | 98.17% | 75.1% |
| The lines alone | Preset | 22.4% | 39.4% | 0.59% | 96.65% | 39.7% |
| The lines alone | Preset, batches of 32 | 0.4% | 20.0% | 0.27% | 94.65% | 22.9% |
| The lines alone | Preset, weight decay 100 | 44.2% | 55.4% | 0.67% | 97.32% | 52.2% |
| The lines and 4,998 corpus samples | Preset | 0.5% | 30.9% | 0.62% | 97.47% | 69.3% |
| The lines and 19,998 corpus samples | Preset | 0.6% | 40.3% | 0.93% | 97.89% | 72.8% |

The preset is `TrainConfig::fine_tuning()`. Batches of 32 double the number
of steps on the same lines. The corpus samples come from seed 2, the
validation split of `models.json`, and the test split is seed 3. The default
model was trained on neither; `train.py` uses the validation split only for
its report.

With the `train` example, the last row is the following, where `flagged.txt`
holds the lines to correct, one on each line. The 1,000 lines of the
measurement are not in the repository.

```sh
python3 -B tools/train/dataset.py --seed 2 --count 20000 --out "$WORK/replay.bin"
cargo run --release --features train --example train -- --base default \
  --benign flagged.txt --corpus "$WORK/replay.bin" --out "$WORK/tuned.s2fp"
```

- The lines alone remove the false positives together with the recall of
  `command_injection`, and more steps remove more of both. The model learns
  that the features of a shell command are benign.
- Weight decay, which pulls the weights back to the base model, trades one
  effect against the other. The result is worse at both than tuning together
  with corpus samples.
- Corpus samples keep the recall within a few points of the base model, and
  more of them lose less recall.
- The correction carries over to lines built from other commands only in
  part.

## Limits

- The model has not been measured on real traffic. The results above come
  from the same generator as the training data, so they overstate how well
  the model does on text that the generator does not produce. Measure false
  positives on your own traffic before acting on a threshold.
- Benign text that the generator does not cover can score high. A known
  example is a shell command quoted in prose or documentation, which scores
  as `command_injection`. The benign data contains relative paths that
  climb one or two levels to an ordinary file, but a deeper `../` chain or
  one that reaches a well-known sensitive file is always an attack in the
  training data.
- `command_injection` has the lowest recall. Short shell fragments share
  most of their bytes with ordinary text, and the model misses many of them
  rather than flag that text.
- Very short inputs carry little evidence. The development set shows misses
  on short fragments; the one development string that the model misses is a
  15-byte percent-escaped overlong sequence, which it scores as
  `obfuscation` but not as `malformed`.
- The attack grammars cover common textbook forms of each category. They are
  not a catalog of evasion techniques, and an attacker who knows the model
  can search for inputs that score low.
- Scores are not calibrated probabilities.
